## 三、十三个手法，逐个对照

1. **设计令牌**：`base.css` 顶部 `:root` 里 15 个变量决定全站观感。改 `--accent` 一个值，按钮、链接、光晕、对勾全跟着变。
2. **流体字号**：`clamp(38px, 7.2vw, 88px)` —— 最小值、随视口缩放、最大值三件套，替代一堆媒体查询。
3. **排版对比**：标题 `font-weight:700` + `line-height:1.05`，正文 `400` + `1.65`。对比越极端越显贵。
4. **滚动渐显**：`IntersectionObserver` + CSS 变量 `--rd` 做交错延迟，`unobserve` 保证只播一次。
5. **毛玻璃吸顶**：`backdrop-filter: blur(20px) saturate(180%)`。只 blur 不发灰的关键是 `saturate`。
6. **吸顶视差**：外层 `height:200vh` + 内层 `position:sticky`，多出来的一屏就是动画时间轴；JS 只输出 `--p`（0→1）。
7. **吸附画廊**：`scroll-snap-type:x mandatory` + `scroll-snap-align:center`，零 JS 也有 iOS 手感；`hover.js` 只额外加了拖动。
8. **数字缓动**：`easeOutCubic` + `font-variant-numeric:tabular-nums`（少了后者，数字跳动时整块会左右抖）。
9. **主题切换**：只改 `data-theme` 属性覆盖变量，不重写任何规则；`transition` 挂在 `body` 上，切换时整页柔和过渡。
10. **无障碍降级**：`prefers-reduced-motion: reduce` 时 CSS 关掉全部动画，JS 直接 `return` 不注册监听。
11. **磨砂面板**：把 `backdrop-filter` 放在一层全屏遮罩上，导航和面板只改成半透明 —— 一块模糊糊全站，比每块玻璃各自模糊既省性能又没有拼接边。展开动画用 `max-height` + `visibility`，不是 `display`。
12. **一个委托监听**：全站点击只挂在 `document` 上，先认触发器、再认"面板外"，遮罩/正文/空白区不用分别写监听，逻辑只有两处、不会互相抢事件。
13. **整组替换的轮播**：`display:flex` + 每格 `flex:0 0 100%`，轨道只吃一个 `--i` 就走出整组左右滑；一屏几格放在 CSS 令牌 `--view` 里、由 JS 读回来算步数，所以改断点不碰脚本。详见 8.3。

## 四、四个最容易踩的坑（本页已处理，你搬代码时别丢）

- **渐显把内容永久藏起来**：所有渐显规则都以 `.js-ready` 为前提（`effects.css` 开头）。JS 出错或被拦截时，元素根本不会被打上隐藏样式。
- **瞬移滚动跳过回调**：`IntersectionObserver` 按帧采样，用 JS 瞬间 `scrollTo` 时中间的元素一帧都没进过视口，回调不触发 → 永远透明。`reveal.js` 末尾的 `sweep()` 就是补这个的，`nav.js` 滚完锚点还会主动调一次。
- **锚点跳过去标题被导航盖住**：`nav.js` 里目标位置减了 `nav.offsetHeight`，这是吸顶导航配套的必修修正。
- **backdrop-filter 会让元素变成 fixed 后代的"囚笼"**：`.nav.is-stuck` 有 `backdrop-filter`，如果下拉面板写在 `.nav` 里面并靠 `position:fixed;top:var(--nav-h);bottom:0` 铺满剩余屏幕，那个 `top/bottom` 会以**导航自己的盒子**为基准算。实测：同一个 `top:52px;bottom:0` 的 fixed 元素，放进带 backdrop-filter 的 `.nav` 里高度算成 **0px**，写在 `<body>` 里则正常铺满导航以下的整屏。所以面板必须和导航做兄弟节点（写在 `</header>` 外面）。

## 五、怎么把技巧搬进 `E:\网页\index.html`

1. 先只搬 CSS：把 `effects.css` 里你需要的那一小节，粘到 `index.html` 的 `<style>` 结束前。
   **绝对不要**在 `<style>` 里写 `<!--` 或 `</style>`，前者会被当成 CSS 的 CDO 记号吞掉后面的规则，后者会直接截断样式表 —— 这两个坑你都踩过。
2. 再搬 JS：粘到 `</script>` 前，保持"包在 IIFE 里"的形状。
   注意：你现在 `index.html` 的脚本里已经有 400 多行 `<!--` 行注释，这是浏览器允许的写法，但**一旦把 JS 拆成独立 `.js` 文件就会报错**。这个教学目录里的 `.js` 文件用的是 `/* */` 和 `//`，就是为了让你习惯正确写法。
3. 类名先对齐：本页用 `.js-ready`，你的 `index.html` 用 `.anim-ready`，两边挑一个。
4. 搬完一定在浏览器里实测：F12 → Console 无报错，且**关掉动画后内容仍然全部可见**。

苹果产品页那种"滚一下、画面变一档"的效果，原始做法是几百帧序列图 + 滚动抽帧。
这里用你现有的 4 张实拍图做了等效版本，原理是三句话：

1. 外层 `.scrub` 高度 = `每帧 200vh × 帧数`（窄屏覆盖为 150vh），内层 `.scrub__stage` 用 `position:sticky` 钉住一整屏 —— 多滚出来的高度就是动画时间轴。
2. `js/scrub.js` 每帧只算两个数写进 CSS 变量：`--o`（这一帧此刻多不透明）、`--k`（这一帧在自己窗口里走到第几步）。
3. `css/scrub.css` 拿这两个数做视觉：`opacity:var(--o)`、`transform:scale(calc(1.04 + var(--k)*.10))`。

两个值得记住的细节：

- **淡化曲线用 smoothstep**，因为 `s(t) + s(1-t) = 1`，所以相邻两帧的透明度之和恒为 1 —— 交叉淡化时画面不会"暗一下"。实测整段 `sum(--o)` 始终等于 1.000。
- **字幕出现阈值必须 > 0.5**（这里写的是 0.55，斜率 2.2）。因为相邻两帧 `--o` 之和为 1，两帧同时超过 0.55 是不可能的 —— 数学上保证任何时刻只有一条字幕可见。默认值调小时会出现两行字叠在一起的脏画面，这个坑我已经踩过一次。
  反过来，斜率也不能太陡：曾经为了消重叠把斜率提到 3.5，结果字幕是"啪"一下跳出来的，完全没有淡入手感。**互斥靠阈值 >0.5 保证，跟斜率无关**，斜率只管软硬。

想加一帧：复制一个 `<figure class="scrub__item">`，换图片和文案即可，帧数由 JS 自动数出来（写进 `--n`，总高度跟着变）。
想改快慢：只改 `css/scrub.css` 里的 `--per`（每帧占用多少 vh），窄屏另有覆盖。

## 七、苹果式磨砂下拉面板（`index.html` 的导航）

点导航栏目 → 面板从导航下面展开，同时整页背景被糊掉压暗。这一段最容易做错的地方是"磨砂到底加在谁身上"。

### 分工

| 东西 | 文件 | 干什么 |
|---|---|---|
| `.menu-scrim` | CSS | `position:fixed;inset:0;z-index:40` 全屏遮罩，`backdrop-filter:saturate(160%) blur(18px)` + `rgba(10,13,18,.26)`。**整页背景就是在这里被糊的** |
| `.nav.has-menu` | CSS | 只把背景换成 76% 半透明，让下面那层磨砂透上来 |
| `.menu` | CSS | 面板本体，`z-index:51`、`top:var(--nav-h)`、**自己不加 backdrop-filter**，靠 `color-mix(… 72%, transparent)` 透出被糊过的页面 |
| `js/menu.js` | JS | 只切类名和 `aria-*`，一个数值都不写 |

一句话记住：**模糊只放一层，放遮罩上。** 面板自己再叠一层 `backdrop-filter`，它要糊的东西其实已经被遮罩糊过一遍了，叠上去只会更糊更费性能；而导航和面板是两块分开的区域，各糊各的还会在交界处露出两条模糊边界。

### 展开动画为什么用 `max-height` 而不是 `height`

`height:auto` 不能过渡。所以是 `max-height:0 → min(72vh,560px)`，配合 `opacity` 和 `transform:translateY(-6px)`。
隐藏状态用 `visibility:hidden` **而不是 `display:none`**：`display:none` 直接没有过渡，而 `visibility` 既能淡入淡出，又能把里面的链接踢出 Tab 顺序（实测面板收起时 47 个链接 0 个可达）。

### 交互规则（`js/menu.js`）

**主路径是鼠标悬停，不用点**（和苹果一样）：鼠标在栏目上停 140ms 就自动展开，移到别的栏目立刻换面板，鼠标离开"导航+面板"这块区域后自动收起。
点击那条路也保留着，给触屏和键盘用：点栏目展开、点外面或 `Esc` 收起、再点同一个栏目也收起。

- **只有"飘开的"面板才随鼠标移走自动收起，点开的不会** —— 一个 `byHover` 标记区分。触屏上 `pointerenter` 在点按时也会派发，所以整套 hover 逻辑先用 `matchMedia('(hover:hover) and (pointer:fine)')` + 宽屏两个条件把关，手机用户不会被莫名其妙的面板糊住屏幕。
- **140ms / 260ms 两个延时是手感的关键**，都得留在 JS 里（它们是行为参数，不是样式数值）：
  进栏目要停一下才开，否则鼠标斜着划过导航会连着闪四五个面板；
  离开设 260ms 才关，因为导航和面板是兄弟节点，指针从导航移进面板时会先派发 nav 的 `mouseleave`、再派发 panel 的 `mouseenter`，中间空一两帧，延时太短面板会自己抖一下收起（实测这两个事件都靠 `mouseenter/mouseleave` 而不是 `mouseover/mouseout` —— 后者在区域内部从一个字移到另一个字都会触发，面板根本没法保持打开）。
- 全站点击只有一个 `document` 级委托监听：先认触发器（`preventDefault` 后开面板），剩下只要不是落在已打开的面板里，一律当"点外面"收起。遮罩、正文、导航空白都是这一条覆盖的，不用各写一个监听。
- 点面板里的链接：先收起、**不**把焦点抢回导航，再让 `js/nav.js` 去做平滑滚动。两个脚本都会监听 `a[href^="#"]`，所以 `nav.js` 里加了一行 `if (a.hasAttribute('data-menu')) return;` 让位，否则两边都 `preventDefault`，点了打不开。
- `Esc` 收起并把焦点还给触发器；**故意不监听 Tab** —— 打开后焦点仍留在栏目上（苹果行为），Tab 就关面板的话键盘用户反而进不去。
- 开面板时 `body.menu-open{overflow:hidden}` 锁滚动，同时 `html{scrollbar-gutter:stable}` 预先占住滚动条那 17px，否则锁滚动的瞬间整页会横向跳一下。

### 怎么加一个栏目

1. 导航里加触发器：`<a href="#xxx" data-menu="xxx" aria-expanded="false" aria-controls="menu-xxx" aria-haspopup="true">名字<span class="caret" aria-hidden="true">▾</span></a>`
2. `</header>` 下面加面板：`<div class="menu" id="menu-xxx" aria-hidden="true"><div class="menu__inner"><div class="menu__cols">…</div></div></div>`
3. **`id` 必须是 `menu-` + `data-menu` 的值**，这是 JS 唯一的查找规则，改哪边都要改两边。

窄屏（≤760px）自动切成汉堡按钮 + 整屏菜单，用的是 `#menu-all` 那个面板，它只有一列。

### 8.3 两个自动轮播（`css/carousel.css` + `js/carousel.js`）

2026-10-02 加的功能：首屏"标题 + 产品图"整组左右替换（品牌主张 + 四个产品方向，共 5 屏），六个主力方向的卡片整批左右轮播，都自动循环。

**还是那条分层原则**：`carousel.js` 只往轨道上写一个数 `--i`（当前第几格），
位移全部由 CSS 算：

```css
/* 首屏：一屏占满，翻一屏正好走一个自身宽度 */
.hcar__stage  { transform: translateX(calc(var(--i,0) * -100%)) }
/* 卡片：一格宽 = (100% - 缝) / view，翻一格就走 -(一格 + 一缝) */
.gcar__track  { transform: translateX(calc(var(--i,0) * -1 * (100% + var(--car-gap)) / var(--view))) }
```

几个当时想过、后来定下来的点：

1. **CTA 不跟着转**。"说需求"和"看产品分类"两个按钮留在旋转区外面常驻——主入口不能哪一屏都找不到。
   产品卡轮播下面那个"进产品中心 · 16 大类 101 款"同理，在轮播容器外面。
2. **一屏几格写在 CSS 里**（`--view:3`，900px 以下 2 格，620px 以下 1 格），末尾补几格克隆写在 `--car-clone` 里（等于最宽那档的 `--view`）。
   JS 用 `getComputedStyle` 把它们**读**回来，所以改断点只用改 CSS，JS 不用动。
   **回卷是单向的，不倒带**：脚本按 `--car-clone` 在轨道末尾补克隆格（首屏 1 屏、卡片 3 格），
   位置 `i = n` 的画面和 `i = 0` 完全一样，走到这里就用 `transition:none` + 一次强制重排无动画归零，肉眼看不出来。
   于是"最右再往右"是第一张从右边推进来，"最左再往左"是最后一张从左边走进来，都只走一格。
   克隆格带 `aria-hidden="true"`、里面的链接 `tabindex="-1"`，首屏那格的 `<h1>` 在克隆里降级成 `<div class="t-hero">`，全站仍然只有一个 `h1`。
3. **回退是"原版式"，不是"空白"**。所有藏格子的规则都挂在 `.is-run` 上，
   没有脚本 / 开了"减少动态效果"时：首屏只显示第一屏、圆点消失；六个方向退回原来的三列网格，六张全在。
   卡片轨道用的是 `display:contents`——不启用轮播时它等于不存在，卡片直接落进外层网格。
4. **三种暂停**：鼠标悬停、键盘焦点落进轮播、切到别的标签页。
   读屏或者伸手点链接的时候画面不能自己跑掉。点圆点/左右按钮会重新计时。
5. **触摸横向拖**是跟着手指实时走的（`--i` 写成小数，CSS 的公式天然吃小数）。
   起手先判方向：竖向位移大就整个交还给浏览器，不然手机上滑页面会被轮播抢走。
6. **首屏只有一个 `h1`，而且它就是看得见的品牌主张**。第一屏 `.hcar__slide--brand`（"多品牌仪器 / 一站式选型"）
   直接写成 `<h1>`，后面四屏产品标题并列、用 `<h2>`。这样语义和视觉是同一句话，
   不需要再藏一个只给读屏器的 `h1`；`carousel.js` 也不管标签名，它只数 `.hcar__slide`。
   品牌屏排在第一还有一个好处：脚本失效或开了"减少动态效果"时只剩第一屏，看到的正好是加轮播之前那张静态主视觉。
   字号上它不跟产品屏收缩（`base.css` 的 `clamp(38px,7.2vw,88px)` 原样），
   收缩规则写成了 `.hcar__slide:not(.hcar__slide--brand) .t-hero`，避免把同一个 `clamp` 抄两遍。
7. **产品图上限高度用 `clamp(…,vh,…)` 写在每张图的 `style="--h:…"` 上**。
   四张图比例差得很大（246×520 的长条 vs 760×392 的横块），统一给一个高度会让横的糊成一团，
   所以每台单独调；`width:auto;height:auto` + 两个 `max-` 让浏览器自己保比例。
   投影用 `filter:drop-shadow()` 不用 `box-shadow`——图是透明的，`box-shadow` 会打出一个矩形灰块。
   屏与屏高度差不会让下面的 CTA 跳动：`.hcar__stage` 是 `display:flex`，整条轨道的高度 = 最高那一屏的高度，
   每屏自己 `align-items:center;justify-content:center`，矮的居中、高的撑住，容器整体高度恒定。

**不要这个功能**：删掉 `index.html` 里 `carousel.css` 的 `<link>` 和 `carousel.js` 的 `<script>` 两行，
版式自动回到加轮播之前。文案和图片在 `index.html` 里，加一屏就复制一个 `.hcar__slide` 改文案和图片
（顺序就是 HTML 里的先后，屏数脚本自己数），记得在 `.hcar__dots` 里补一个对应的 `<button role="tab">`。

   会吃掉所有 `[data-menu]` 触发器自己的 `href`，所以点"产品"永远只开面板、不跳页。要"一键可达"就得另给一个能点的入口：
   导航右侧常驻 `.nav__enter` 胶囊（滚到任何位置都在），窄屏两个胶囊挤不下时先收 `.nav__quote`（≤560px 隐藏，整屏菜单里还有），入口本身不能收；
   `css/menu.css` 里给 `.nav__tools` 补了 `margin-left:auto` —— 横向栏目在 ≤760px 是 `display:none`，右对齐原本是靠它的 auto 撑出来的，栏目一隐藏工具区就黏在 logo 后面。
   另外把面板里 8 个分类项、首页 6 张方向卡的箭头都改成深链 `products.html#cat-xxx`，点哪一类就直接落到哪一类。
   实测：`index.html` 里指向产品页的链接 22 处，胶囊点下去导航不会被 preventDefault 吃掉。
5. **深链落点的坑（这一条最费时间）**：`#cat-xxx` 在加载时用**平滑**滚动会翻车 ——
   浏览器自己的"恢复上次滚动位置"会在 `load` 之后异步再滚一次把跳转顶掉，而且平滑动画的目标点会被当时的
   "最大可滚距离"夹住，动画走到中途就停住不再修正，实测落点比目标差 3000~8000px。
   `products.js` 现在只在带 `#cat-` 进来时把 `history.scrollRestoration` 设成 `manual`（其他情况保留默认，后退键照常还原位置），
   先瞬移一次、`load` 之后再瞬移校正一次，并立刻补扫渐显。实测两类页（`#cat-semi` / `#cat-polymer`）落点都是吸顶条下 8px。
   **凡是"进页面就跳到中段"，都要管这两件事：滚动恢复会抢、目标会被最大滚动距离夹住 —— 所以用瞬移，不用平滑。**
6. **产品图统一影棚模板（`img/products-studio/`，97 张 / 2.6MB）**：画册原图有 44 张原生宽度不足 200px，
   直接放进卡片又糊又像"白底贴纸贴在灰卡片上"。做法**不是重画**（AI 重画会改动机身颜色、屏幕内容、logo 位置，一眼就和实物对不上），
   而是**只换背景、一个像素都不动设备本身**：浏览器 canvas 从四条边往里泛洪，把和边框连成一片的近白吃掉（≥238 全透、220~238 半透做羽化），
   裁出包围盒后合成到 800×500 的浅灰渐变底板上，中间叠一点径向高光，底部画一条压扁模糊的椭圆当接触投影。
   四个必须记住的点：
   - **泛洪只能从边框种子开始**，用全局阈值会把白色机身的设备整台挖没；
   - **抠不动的图不要硬抠**，模板有两级兜底：白底抠不掉（吃掉面积 <12%）就先重画原图、换成"吃近黑"再抠一次
     （黑底棚拍图走这条路：`p10-1 p11-1 p27-2`）；两轮都抠不动的（浅紫灰底这种不上不下的背景）走"延长背景"模式
     （`p16-4 p16-6 p28-4`）：取原图上下两条边缘的平均色，用它铺满整块底板，照片四边再羽化 22px 咬进去——
     颜色一致所以接缝直接消失，看着就是影棚无缝背景纸。**别用"圆角照片贴一块"的做法**，那块浅色方块压在灰底板上边界一眼就露。
   - **占比要统一，放大上限锁 3.2×**：设备包围盒放到占底板宽 80% / 高 74%（取小的那个），
     画册里只给到 56~118px 的十几张小图不放大就会在网格里显得特别小；底板出 800 宽而不是 640，
     是因为桌面三列时图框约 417 CSS px，2x 屏要吃 834px，800 才算刚好不拉伸。
   - **放大完必须补锐度**：canvas 放大走双线性插值会把边缘抹平，所以合成完再做一次非锐化掩模
     （`原图 + 量 ×(原图 − 高斯模糊)`，量随放大倍率从 0.28 涨到 0.8，半径 2px）。
     这一步只能在**合成之后**做 —— 抠图阶段的画布是透明的，模糊会把透明边拉出一圈暗光晕。
     补锐度只能找回被插值抹掉的边缘，**变不出原图里没有的细节**，那十几张 <120px 的图放大到 100% 看仍然是软的，这是画册原图的天花板。
   配套的样式改动：`.pc-img` 从"186px 定高 + contain + 16px 内边距"改成 `aspect-ratio:8/5` + `cover`，
   比例和底板完全一致，所以 cover 不会裁到设备，图也铺满整格不再像贴纸。
   `render-products.mjs` 按文件是否存在决定用新图还是回退原图（`img/products/` 一张没删，随时整体退回）。
   脚本在 `C:\Users\NIUMAG\AppData\Local\Temp\jiyao_tools\studio.mjs`（本地起 8733 端口，Node 只当文件服务器，抠图/缩放/JPEG 编码全交给 Chrome canvas，质量比手写实现强）。
   核对效果：`/keys` 列待处理、`/out/<图>` 读成品，把 97 张拼成一张总览图存成 `_sheet.jpg` 一眼看全（看完记得删，别留在站点目录里）。

7. **顶部导航不写第二遍，生成时从 `index.html` 搬**（`render-products.mjs` 里的 `sharedNav()`）：
   产品页原来手写了一份简化导航（没有下拉面板、没有 caret、"产品中心"是个普通链接），首页一改成"悬停展开 + 胶囊入口"，
   两页顶部立刻长得不一样。**同类页面的顶栏只要允许，就只应该有一份源码。**
   搬过来只做三处改写，顺序不能换：
   - `href="#x"` → `href="index.html#x"`（首页站内锚点变跨页）；
   - `href="products.html#x"` → `href="#x"`、`href="products.html"` → `href="#top"`（指回本页的走本地锚点，不重新加载）；
   - 给"产品中心"胶囊打 `aria-current="page"`，`css/menu.css` 里一条 `[aria-current="page"]{background:var(--accent);color:#fff}` 把它填实 ——
     首页没这个属性，所以两页结构完全一致、当前页又看得出来。**不用 `.is-active`**，`nav.js` 的滚动高亮会把所有 `.is-active` 抢走。
   配套要在产品页带上 `css/menu.css` 和 `js/menu.js`（后者必须紧跟 `nav.js`）。
   `sharedNav()` 里两处 `throw`：找不到 `<header class="nav">`…`<main id="top">` 区间、或找不到 `nav__enter` 胶囊就中止生成，
   首页结构改了会立刻报错，而不是悄悄生成一份旧导航。
   实测：产品页 5 个栏目全带 caret 和面板，悬停 140ms 展开 / 移开 260ms 收起（窄屏 ≤760px 时 `canHover()` 主动禁用悬停，只剩汉堡）；
   胶囊底色 `rgb(0,113,227)`、首页那颗仍是透明描边。

   还补了一个只在共用之后才暴露的坑：面板里的分类链接走 `nav.js`，而 `nav.js` 不知道搜索筛选还开着 ——
   筛着"疲劳"再点分类，目标 section 可能正被 `display:none` 着，量出来的落点差 24000px。
   `products.js` 加了一个**捕获阶段**的 `document` 监听，抢在 `nav.js` 的锚点监听之前把筛选清掉
   （捕获必须先于目标元素上的监听，绑在普通阶段就晚了）。
   实测：先筛"疲劳"（11/101）再从面板点"力学性能测试"，落点距筛选条底边正常，计数回到 101。
